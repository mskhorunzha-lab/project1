# Портал управления ИТ-инфраструктурой

MVP web-портала (portal v.0) по концепции управления направлением инфраструктуры производственного предприятия.

## Пилотный охват

- Реестр оборудования (ИБП, СКУД)
- Журнал работ инфраструктуры
- Плановое ТО с автосозданием задач
- Чек-листы ТО ИБП и СКУД
- Склад ЗИП и журнал движений
- Импорт CSV/XLSX
- Отчёты: просрочки, склад, KPI

## Требования

- Node.js 18+
- Docker (для PostgreSQL) или существующая БД PostgreSQL

## Быстрый старт

```bash
# 1. Установить зависимости
npm install

# 2. Запустить PostgreSQL
docker compose up -d

# 3. Настроить окружение
copy .env.example .env

# 4. Создать схему и демо-данные
npm run db:push
npm run db:seed

# 5. Запустить портал
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000)

## Разделы портала

| Раздел | Назначение |
|--------|------------|
| Дашборд | KPI, просрочки, дефицит ЗИП |
| Оборудование | Единый реестр объектов |
| Работы | Внутренний таск-трекер |
| ТО | Регламенты, графики, автозадачи |
| Склад | Остатки, движения, списание |
| Отчёты | Просрочки, закупки, KPI |
| Импорт | CSV/XLSX оборудования и склада |
| Администрирование | Роли, регламенты |

## Импорт данных

Шаблоны: `public/templates/equipment.csv`, `public/templates/warehouse.csv`

Поддерживается:
- UTF-8 и Windows-1251
- Разделители `;` и `,`
- XLSX
- Upsert по external ID
- Ограничение размера файла: 5 МБ
- Ограничение строк: 5000

Формат XLS больше не принимается в целях безопасности. Для Excel-файлов используйте XLSX.

## Безопасность и аудит

Мутации API защищены проверкой роли пользователя. Для production-запросов нужно
передавать один из идентификаторов текущего пользователя:

- cookie `infra_user_id`
- header `x-user-id`
- header `x-user-email`

Для локального/demo режима можно задать `INFRA_PORTAL_DEFAULT_USER_EMAIL` в `.env`.
Если переменная не задана, в непроизводственной среде будет выбран первый активный
пользователь с ролью `ADMIN` или `MANAGER`.

Все критичные мутации пишут события в `AuditLog`:

- создание оборудования
- создание и смена статуса работ
- сохранение чек-листов
- генерация задач ТО
- складские движения
- импорт данных

запускает Prisma validation, typecheck, lint, тесты и production build.

## Связь с концепцией

Портал **не заменяет Service Desk** — поле `serviceDeskTicket` связывает работу с обращением.

Правила:
- Нет задачи — нет работы
- Нет чек-листа — работа ТО не принята
- Нет основания — нет списания ЗИП
